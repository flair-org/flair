# Flair CLI Domain Glossary

Core domain language for the Flair CLI model-weight version control and federated learning system.

## Roles & Identity

**Admin**:
A repository maintainer with authority to register the base model, configure repository governance, and publish federated merge commits.
_Avoid_: Superuser, root, owner, manager

**Contributor**:
A participant who clones a repository, pulls model weights, trains locally, and submits validated parameter updates for merge.
_Avoid_: Worker, client, agent, node

## Model Lifecycle & Storage

**Base Model**:
The immutable founding model weights registered at repository initialization, serving as the root ancestor for all parameter deltas.
_Avoid_: Pretrained model, seed weights, root model

**Checkpoint Commit**:
A commit storing a complete snapshot of all model parameters, serving as a boundary for reconstruction.
_Avoid_: Full commit, snapshot commit, baseline

**Delta Commit**:
A commit recording only the mathematical difference between updated model weights and their parent commit.
_Avoid_: Diff commit, incremental commit, gradient update

**5-Step Commit Lifecycle**:
The atomic sequence (`add` → `params create` → `zkp create` → `commit` → `push`) required to stage, prove, sign, and publish model weights.
_Avoid_: Commit workflow, staging pipeline

**Federated Merge**:
The process where an Admin combines one or more Contributor parameter updates and stages an authoritative checkpoint commit on a branch.
_Avoid_: Weight aggregation, Git merge, sync

## Verification & Proofs

**Zero-Knowledge Proof (ZKP)**:
A succinct cryptographic proof generated via EZKL demonstrating verifiable execution of model inference or metric computation without exposing private evaluation datasets.
_Avoid_: ZKML proof, audit proof, validity token

## Remote Synchronization

**Push Manifest**:
A structured specification generated by the CLI during `flair push` describing the repository target, branch ref, and local commit DAG to negotiate required artifact transfers with the backend.
_Avoid_: Push payload, push request, sync packet

**Push Handshake**:
The negotiation phase of `flair push` where the backend evaluates the Push Manifest and responds with the exact set of missing commits, parameters, and proof artifacts to be transferred.
_Avoid_: Upload negotiation, push sync, pack negotiation

**Commit Hash Reconciliation**:
The atomic process where the CLI replaces temporary local commit UUIDs and parent pointers with the authoritative SHA-256 hashes returned by the backend after push completion.
_Avoid_: Hash overwrite, commit remapping, commit sync

**Local-First Workspace**:
A Flair repository initialized and operated entirely on the local machine with offline UUID v4 identifiers, requiring no backend communication until an explicit push.
_Avoid_: Offline repo, unlinked repo, detached workspace

## Security & Authentication

**SSH Agent Activation Script**:
A platform-specific script (`.cmd` for Command Prompt, `.ps1` for PowerShell, or `.sh` for Bash) generated by `flair auth ssh env` to ensure the system `ssh-agent` service is running and load the user's signing key into memory.
_Avoid_: SSH bootstrap, key runner, agent loader

**Terminal Environment Detection**:
The automatic runtime inspection mechanism that identifies whether the calling session is Windows Command Prompt (CMD), PowerShell, Git Bash, or a POSIX shell without requiring manual `--shell` parameters.
_Avoid_: OS guessing, terminal sniffing
